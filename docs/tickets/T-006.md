STEVEN_LEARNING_NOTES:
- L’authentification vérifie l’identité ; l’autorisation vérifie les droits d’action.
- Une session permet au serveur de reconnaître un utilisateur authentifié entre deux requêtes.
- CSRF protège contre l’envoi d’actions à l’insu de l’utilisateur authentifié.
- Le hash d’un mot de passe est non réversible ; il ne s’agit pas de chiffrement.
- Django Auth est utilisé pour éviter de réimplémenter hachage, sessions, CSRF et redirections sécurisées.
- Un utilisateur inactif est refusé afin que la désactivation de compte ait un effet immédiat.
- Cacher une page dans l’interface ne constitue pas une autorisation : les contrôles doivent rester côté serveur.
- JWT n’est pas nécessaire pour ce MVP Django server-rendered utilisant des sessions.
- Après logout, la session est invalidée et la page protégée redevient inaccessible.

LIMITATIONS:
- pas de récupération de mot de passe, OAuth, MFA, JWT, API REST, React ou connexion par email.
- pas de CRUD utilisateur, dashboard fonctionnel, upload, recherche, audit ni RBAC d’archives.

RISKS:
