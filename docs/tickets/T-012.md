STEVEN_LEARNING_NOTES:
- Un journal d’audit est un historique structuré des opérations métier importantes, distinct des logs techniques de serveur.
- actor répond à qui a agi ; action répond à quoi ; archive répond à quelle ressource ; timestamp répond à quand.
- L’IP est un contexte supplémentaire, pas une preuve d’identité à elle seule.
- Append-only signifie qu’aucun utilisateur standard ne peut modifier ou supprimer une entrée par l’application.
- Les détails minimaux évitent que le journal devienne une nouvelle source de fuite de secrets ou de données confidentielles.
- Les signaux Django conviennent à login/logout ; les vues explicites sont plus précises pour les actions d’archive.

LIMITATIONS:
- application-level append-only.
- no immutable external SIEM.
- no cryptographic log chaining.
- no delete event because physical delete does not exist.
- no LOGIN_FAILED event in the MVP.

RISKS:
- une garantie d’immutabilité forte exigerait un stockage externe, une rétention et des contrôles d’infrastructure validés avec C-Tech.
- une stratégie de proxy de confiance devra être définie avant toute interprétation de X-Forwarded-For.
- l’accès administrateur au journal doit rester limité car il peut référencer une archive CONFIDENTIAL.

QUESTIONS_REQUIRING_C-TECH:
